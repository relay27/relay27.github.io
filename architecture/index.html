01 / FIELD NOTES

Separate language from authority.

A speech/model adapter may extract fields and ask approved clarification questions. A server-side policy engine decides which allowed action follows. Treat everything the caller says as untrusted input, not as a command to the application.

Ingress

Validate provider signatures; associate the call with a tenant; attach a correlation ID. Never trust a tenant ID supplied by the caller.

Intake

Disclose automation. Obtain appropriate consent before recording or transcription. Support a human alternative. Confirm essential fields and mark unknown values explicitly.

Policy

Apply service-area, opening-hours and escalation rules. Uncertainty goes to review. No autonomous eligibility, price or safety decisions.

Delivery

Queue the service request. Use idempotency keys to avoid duplicate jobs when webhooks retry. Require acknowledgement for an escalation.

Fallback

When streaming, model or notification delivery fails, follow provider-level routing to an approved human destination or clearly disclosed callback path.

02 / FIELD NOTES

A contract, not a transcript dump.

Illustrative schema only. Production requests need validated identifiers, encryption, role-based access, retention controls and an audit trail. Keep secrets on the server; never commit API keys to GitHub Pages.

03 / FIELD NOTES

The Pi belongs on the bench first.

A Raspberry Pi could drive a workshop status panel, a test handset or a local network monitor. It is optional. A disconnected hobby device must not become the single point of failure for customer calls.

The public site is static documentation and a routing simulation. Real telephone service requires a separately deployed backend, provider account, credentials and a reviewed operating policy. No production backend is included in this MVP website.
